# Search beyond the words typed

- **Status:** Active (2026-10-20)
- **The owner (2026-10-20):** "Broader search is good." (built as the [portable reports](portable-reports-2026-10-19.md)' milestone 6: words, phrases, fields, the most relevant first, `like:ID`). Then, on the four ideas proposed beside it: "I like all the ideas for search. So, lowest hanging fruit first, I guess."
- **Earlier (2026-10-20), on unrelated pairs:** "As a user of the report, it would be convenient to have an easily searchable database of claims even without the comparisons."

## Why

The page's search finds the words typed, wherever a claim holds them. It misses three kinds of match:
- **Another name:** two documents name one thing differently ("rated output", "nominal power"; 8 of the turbines run's 32 related pairs share words in both entity and attribute).
- **Another unit:** "75 kW" and "0.075 MW".
- **Another wording of the meaning.**

It also only searches inside one report; a store's claims can't be searched without writing one.

## Milestones

In order of effort, lowest first.

1. **Counterparts** (done 2026-10-20): the names the documents differ on, from the comparison's own pairs.
   - **In the claims view, with a search:** the claims the findings pair with the found ones are shown too, after them, each marked as a counterpart; a checkbox leaves them out.
   - **The other source's words:** where a found claim's entity or attribute holds the words searched and its counterpart's doesn't (the query doesn't find it), the counterpart's name is offered as a search: "rated output" offers "nominal power".
   - Nothing is added to the file: findings already pair the claims.
   - **On the turbines proposals run** (NREL 5 MW against IEA 15 MW, 711 claims, 128 related findings; 111 pair attributes worded differently):
     - "height above ground" finds 2 claims and 4 counterparts, and offers "height", "hub height" and "ground clearance".
     - "hub height" offers "height above ground" and "overall height", and "tower" for the found claim's entity "hub".
     - "rated speed" offers "Rotor Speed".
2. **Search from the command line** (done 2026-10-20): `semantic-pdf-diff search WORDS --store DIR [--store DIR ...]`.
   - It searches every claim of the stores, with or without a report. It's the database of claims the owner asked for, kept where the stores are.
   - The same query language, fields and ranking as the page: a Python port of `search.js`, held to the page by the same test cases, run by both.
   - It prints claims, most relevant first, with where each is; `--json` for tools; counterparts from the stores' comparisons.
   - **Built:**
     - Each store's latest comparison is searched (`--comparison N` picks another), several stores in one index.
     - The cards are written by `report.Cards` and read by `search.py` exactly as the page reads them.
     - Options: `--findings`, `--side` (a source's name or a part of it), `--alone` (no counterparts), `--limit`, `--json`.
     - A word to leave out needs no quoting (`search pump -gearbox`): the command has no `-h`.
   - **The same answers as the page:** every test case run in headless Chromium is run by `search.py` too.
     - On the turbines and TS 38.300 reports, 17 queries returned the same claims in the same order and offered the same names, up to 2,919 claims a query.
     - TS 38.300's 13,309 claims are indexed in 2.4 s; a search then takes 0.03–0.17 s.
   - **Found on the way:** a bare word searched the file's name too, so "mw" found all 711 of the turbines' claims (`nrel-5mw-p25-36.pdf`). Both now search a file's name only for `file:`.
3. **Numbers across units:** `value:>50kW`, `value:10-20mm`, `value:<0.1MW`.
   - Claims' values are normalized with the units the numeric checks use (`units.py`). The page carries each claim's value in base units and a table of the units its search can parse.
   - The command line reads `units.py` itself.
4. **Names from the model** (a lever, measured): synonyms for the claims' names, asked in or beside the topics' request.
   - Measured by how many related pairs a search for one name finds both of, against counterparts alone.
   - Pennies a comparison.
5. **By meaning** (a lever, measured): claims embedded by a model (DeepInfra serves Qwen3-Embedding).
   - The command line embeds the query too, so it can search by meaning.
   - The page can't embed a query offline, but `like:ID` by meaning works from the claims' vectors, if they fit the budget: 13,000 claims at 256 dimensions, a byte each, are 3.4 MB.
   - Measured on the related pairs words miss.
